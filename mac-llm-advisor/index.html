How the numbers are made

EST.

Weights. params × bits-per-weight ÷ 8 × 1.03. GGUF K-quants use effective bpw (Q4_K_M ≈ 4.85); MLX 4-bit ≈ 4.5 bpw. MoE models count all experts in memory but only active params per token for speed.

KV cache. 2 × layers × KV-heads × head-dim × 2 bytes × context, per model architecture (GQA aware; sliding-window models like Gemma 3 discounted). This is why context length is a memory dial, not a free lunch.

GPU budget. macOS wires roughly ⅔ of unified memory for Metal up to 36 GB and ¾ above — that, minus ~1 GB runtime overhead, is what a model must fit into. sudo sysctl iogpu.wired_limit_mb=N raises it at your own risk (leave ≥6–8 GB for macOS; resets on reboot).

Decode speed. Generation is memory-bandwidth-bound: bandwidth × efficiency ÷ active-bytes-per-token (≈0.6 MLX, ≈0.5 llama.cpp, ×0.7 MoE routing), capped by a GPU-compute term for small models. Long contexts and long prompts run slower; prompt ingestion scales with GPU cores instead.

Tiers are editorial capability classes (S…C) for the model's size era — a B on 8 GB can matter more than an unusable S. Catalog curated early 2026 from popular LM Studio / Hugging Face downloads.

Trust but verify. Everything here is an estimate to shortlist candidates — the real benchmark is your own prompt on your own machine. Not affiliated with Apple, Hugging Face, or LM Studio.
